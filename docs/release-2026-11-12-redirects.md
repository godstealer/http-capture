# HTTP Capture 桌面版更新说明（2026-11-12）

本版包含 0.1.73 之后的桌面改动。正式版本号取同一源码提交的 GitHub Check 编号；跨平台检查、打包和更新附件校验通过后才公开发布。

## 更新内容

- 手动发送 HTTP 请求默认跟随 301、302、303、307、308 重定向，最多跟随 10 次；可在请求的「设置」选项卡关闭。抓包代理转发不受此开关影响。
- 每次跳转分别记录到重放历史，结果面板显示最终响应。301/302 的 POST 和 303 的非 HEAD 请求按浏览器常见行为改为 GET；307/308 保留方法和正文。
- 跳转到其他来源时不转发 Cookie、Authorization 等敏感请求头；拒绝 HTTPS 降级到 HTTP、非 HTTP 目标和循环跳转。草稿及已保存请求会记住开关状态。
- 桌面正式安装包启用 wreq 发送引擎，提供基于 BoringSSL 的 Chrome/Firefox 浏览器预设；与 native、H2/H3 和 httpcloak 并存。仅手动发送可选择 wreq，不改变抓包 MITM 的 rustls 链路。
- 新增显式配置的自定义发送引擎协议：本地程序通过标准输入/输出交换版本化 JSON 请求和响应，可声明 TLS 预设、证书与代理能力；仓内提供不联网的 Go 示例，接口说明见 `docs/custom-send-engine.md`。

## 验证边界

前端定向测试及生产构建通过。Windows 本机先前生成的 `header_state` 测试程序曾被杀软拦截并删除；保持防护开启重新构建后，四项测试通过，原报毒原因仍未确定。自定义引擎示例的真实进程往返测试通过；BoringSSL 与现有 OpenSSL 静态库存在同名符号，证书处理已统一到 BoringSSL，本机 213 项核心单元测试通过。四平台安装包仍须通过同源 Check、打包和签名附件校验。自定义程序的网络行为由其作者负责，仓内示例不连接目标服务器。

本版仅发布桌面安装包。Android 局域网协同抓包仍待真机端到端验收，iOS 仍待签名设备验收；不发布正式移动安装包。httpcloak 保持最新稳定版 v1.7.3，不包含 v1.7.4-beta.1。其余待办见[开发清单](roadmap.md)。

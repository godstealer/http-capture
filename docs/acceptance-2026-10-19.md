## 全局配置迁移首版

操作与边界见[配置迁移说明](config-migration.md)。标准 JSON 不加密；默认清空请求内容和变量值，专用代理密码、CA、本机 Token 始终排除。

- [ ] Windows/macOS/Linux 的导出文件窗口、取消、写入失败和保存路径提示；文件完整可预览，不把失败写入视作成功。
- [ ] 两台设备迁移主题/语言/缩放/监听偏好、集合/环境、规则、插件、脚本和 HTTP MCP 定义；默认安全选项与四个显式选项逐一核对。查看文件确认没有 CA 私钥、本机 Token 或专用代理密码。
- [ ] 只选一个类别时整类替换，MCP 服务/权限无论是否选择该类都重置；替换代理时清除未导入请求/草稿的旧代理关联，替换集合时清除保留草稿中无效的收藏关联，其余未选内容保持现状。源文件缺失的普通白名单偏好恢复默认，可选 Proto/TLS 模板/请求模式缺失时保留本机值；更新跳过值及无关浏览器配置不迁移，首版没有自动合并。
- [ ] 无效 JSON、超大文件、未知 schema、无效规则/源码、预览后并发修改均阻止提交，编辑框原文和原数据库配置保留；未保存集合/草稿阻止导出及导入。
- [ ] 导入停止监听、TUN、MCP/stdio 和活动连接并恢复原系统代理；提交成功后旧界面冻结，桌面原生重启后使用新配置。开发预览需重启内核；仅刷新不绕过要求。
- [ ] 偏好写入失败时提示并保留重试入口，在保存成功前不能直接重启；恢复正常后再次保存不会覆盖未选类别。
- [ ] 提交成功但响应丢失/应用退出后，下次启动在工作区初始化前补写所选偏好，成功确认后未来启动不覆盖用户的新偏好；确认写入失败有重试保护页。只刷新网页及其他打开的窗口仍显示内核重启要求，不写回旧草稿。
- [ ] 监听和 MCP 不自动启用，导入的规则、脚本、插件保持禁用，未导入的脚本/插件保持本机原设置；MCP 权限始终重置，stdio 程序重新配置；上游代理使用新 ID、密码需补填，不关联目标设备旧凭据。
- [ ] 显式导出“上次导入前恢复点”，预览并恢复；确认仅有最近一次恢复点，恢复文件可能含原有业务头/正文/变量/源码，仍无 CA/本机 Token/专用代理密码。恢复后按导入流程重启。

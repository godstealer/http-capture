# 全局配置导出、导入与设备迁移

日期：2026-10-19。状态：**当前开发版已实现标准 JSON 首版，尚未发布；加密迁移、自动合并仍未实现**。0.1.23 发布时只有设计文档，下方保留原设计作为后续规划，不将旧设计中未实现的行为算作本版功能。

目标是在旧设备导出配置，在新设备预览后选择类别导入，恢复常用设置和请求组织。已有集合、规则、会话导出与 SQLite 备份继续保留；全局配置文件不打包捕获流量或设备凭据。

## 已实现的首版：先看这里

入口为 **代理设置 → 配置迁移**。文件是标准 JSON，**不加密**，格式标记为 `http-capture-config`，`schemaVersion: 1`，最多 **16 MiB**；包含导出 ID、毫秒时间戳、来源版本、带版本的分类数据和警示信息。不要手工把数据库备份或旧设计示意 JSON 当作配置文件导入。

### 旧设备：导出文件

1. 先在集合页保存尚未保存的集合/环境修改；请求草稿会在迁移前尝试保存。冲突或保存失败会停止迁移，保留当前内容。
2. 打开 **代理设置 → 配置迁移**，首次使用保留默认勾选状态，再点 **导出全局配置**。
3. 选择文件位置。取消不会导出；失败会显示错误，不会把一次失败当作保存完成。桌面版写本机文件，浏览器开发预览使用下载。

四个导出选项默认都关闭：

| 选项 | 开启后包含什么 |
| --- | --- |
| 包含请求内容和变量值 | 已保存请求/选中的草稿的真实 URL 查询值、启用状态及头值、正文和变量值；可能含 Cookie、认证和业务数据 |
| 包含脚本与插件代码 | 全局脚本、插件代码及库中的脚本内容，还包括可选自定义 ClientHello 模板及 Proto 文本；代码也可能写有密钥，请检查后保存 |
| 包含请求工作区草稿 | 当前请求标签，默认不迁移临时工作区 |
| 包含代理用户名 | 上游代理用户名；代理密码仍始终排除 |

默认导出保留请求组织和配置结构，清空请求头值并停用这些字段，清空正文/gRPC 内容和变量值，移除 URL 中用户名、密码、片段并清空查询参数值。源码、插件和工作区按各自开关决定是否包含。URL 路径、名称及其他配置仍可能带业务信息；这不是通用匿名化工具。即使没有勾选，也不要把配置文件当作可公开分享的数据。

### 新设备：先预览，再导入

1. 安装支持该格式的新版本。打开 **代理设置 → 配置迁移 → 选择配置文件**，或把完整 JSON 粘贴进编辑框。选择/粘贴不会导入或访问文件中的 URL。
2. 点击 **预览导入内容**，检查来源版本、时间、类别数量和警示。预览会按已有业务规则检查结构、URL/规则、源码语法等；语法检查不执行代码。
3. 勾选要迁移的类别，再点击 **导入所选配置并停止网络**。首版按**所选整类替换**；MCP 服务关闭、权限清零**始终执行**，即使未选 MCP 类别。其他未选类别不整体替换，但相关关联会清理：替换代理会清除未导入请求/草稿的旧代理关联；替换集合会清除保留草稿中已不存在的收藏关联。没有自动合并、逐条重命名或保留冲突副本。
4. 成功后页面停在重启提示，防止旧界面把导入结果覆盖。桌面版点 **重启应用**；开发预览需停止并重启开发内核，再刷新页面，仅刷新不够。
5. 重启后检查端口、监听地址、代理地址和规则范围，补填代理密码/外部服务 Token，按需手动启用监听、规则、脚本、插件或 MCP。新设备抓 HTTPS 仍需安装并信任该设备的 CA。

读取预览时会记录配置版本；如果预览后其他窗口、AI 或后台脚本改动相关配置，提交会报版本冲突，不覆盖新内容。重新预览、核对后再提交。编辑 JSON 或重新选择文件会使旧预览失效。任何解析/校验/提交失败都会保留编辑框原文，方便修正后重试。

### 首版能迁移哪些类别

| 类别 | 当前行为 |
| --- | --- |
| 界面与监听偏好 | 仅 17 个明确白名单键：主题、语言、缩放、监听偏好、编辑器/布局等；不包含更新跳过决定、Token 或任意 localStorage 键。选中该类时，源包缺失的普通白名单项在目标设备重置为默认；可选的 Proto schema、TLS 模板及请求模式键缺失时保留本机值 |
| 集合与环境 | 迁移集合、请求、环境与模板；真实内容/变量和源码遵循导出选项，使用目标设备的新版本号 |
| 请求草稿 | 只有导出时开启工作区选项才带入；清理捕获记录关联，不迁移流量历史 |
| 断点、阻止规则 | 校验并替换规则；导入的总开关关闭，等待中的请求和命中计数不迁移 |
| 全局脚本、插件 | 只有开启代码选项才带入；检查语法但不执行，导入后禁用 |
| 解密绕过列表 | 按现有主机规则校验后替换 |
| 上游代理 | 保留无密码配置，导入生成新 ID，不意外关联目标设备旧凭据；`rememberPassword` 关闭，用户名按选项，密码重新填写。本机回环地址需确认新设备的代理端口 |
| MCP 配置 | 可带本机服务端口及无认证资料的 HTTP 外部服务端点；端点本身仍可要求 Token，需在新机补填。选中导入时客户端断开并重新分配 ID。无论是否选择此类，MCP 服务均关闭、权限全关。URL 查询及认证不迁移，stdio 命令/参数不迁移，需在新设备重新设置 |

**始终排除：** 抓包记录与正文数据库、CA 证书/私钥、本机 MCP/开发控制 Token、代理密码和系统凭据库内容、系统代理恢复日志/锁、正在运行的网络连接和 TUN 状态。勾选“请求内容”可能包含复制进请求头/正文的业务凭据，与专用代理密码或本机控制 Token 的排除是不同范围。

导入前会停止网络功能并保存一个**本机恢复点**，相关业务设置在同一 SQLite 事务中提交。上游配置也以 `upstream.profiles.v1` 进入 SQLite，避免导入在 JSON 文件和数据库间只写一半；旧版 `upstream-profiles.json` 会一次迁入，新安装目录无需手工复制它。若导入失败，原业务配置保持不变，但已经停止的网络功能不会自动重启。

所选界面偏好同时保留本机导入批次记录。即使提交成功后的响应丢失，或保存浏览器偏好前应用退出，下次打开页面也会在工作区初始化前补写该批偏好；成功后按批次在本机确认一次，不会在以后每次启动时覆盖你新改的主题等设置。偏好/确认写入失败会停在可重试的恢复页。此批次记录和浏览器确认不进入导出文件；只刷新界面而未重启内核时，仍会停在重启提示。

### 导入前恢复点怎么用

每次成功导入前，目标设备的原配置保存在本机 `config-migration.recovery.v1`，只保留最近一次。重启后回到迁移页，点击 **导出上次导入前恢复点**，得到同格式 JSON；再选择该文件、预览并导入所需类别即可恢复。

**恢复点包含导入前原有请求内容、头、变量及源码，可能含业务凭据。** 它不采用普通导出的默认清空选项；仅在你明确导出时生成文件，需妥善保管。它仍不包含专用代理密码、CA 和本机 Token。恢复也会禁用主动网络/代码配置并要求重启，不能用它迁移设备私钥或恢复正在运行的会话。

### 尚未实现与待验收

加密文件/口令恢复、自动合并和冲突重命名、每条配置单独取舍、跨设备 CA/密码迁移未实现。前端自动测试覆盖偏好白名单/替换/失败回滚、显式导出和预览、类别/CAS 参数、错误保留原文、修改后失效、未保存内容保护和重启回调；各平台真实文件窗口、设备迁移、原生重启及系统代理恢复仍见[待验收清单](acceptance-2026-10-19.md)。

## 原设计记录与后续规划

下面第 1–8 节保留 **0.1.23 发布时的设计**，其中“默认合并”“加密迁移”等描述是后续目标。当前可操作行为、文件格式与范围以上面的“已实现的首版”为准，不应据下文推断已支持自动合并或加密。

## 1. 用户入口与默认流程

设置增加“配置迁移”选项卡，包含“导出配置”“导入配置”和最近一次本机恢复点。首屏只提供推荐操作，高级选项折叠。

导出流程：

1. 点击“导出配置”，默认选择“标准配置”；界面列出包含的类别、排除的内容和需要在新设备补填的项目数量。
2. 应用先处理尚未保存的集合与草稿：已经自动保存的内容直接读取；尚未保存的编辑可选择“保存后导出”或“仅导出已保存内容”，不静默丢弃。保存冲突时保留编辑并停止本次导出。
3. 默认文件名为 `http-capture-config-2026-10-19.json`。通过用户选择的路径保存，先写临时文件并完成校验，再替换目标文件。取消或磁盘写入失败不留下看似完整的成品。

导入流程：

1. 选择配置文件后先离线解析和预检，不立即写入、不访问文件中指定的 URL、不执行脚本或命令。
2. 预览显示来源应用版本、导出日期、类别与数量，以及“新增／保留／替换／重命名／需补填／不支持”的摘要。默认选择“合并到当前配置”。
3. 点击“导入”完成一次提交，并自动保留导入前恢复点。结果页直接列出下一步，例如“补填 2 个代理密码”“当前监听地址在本机不可用”“安装本机 CA 证书”。
4. 导入不自动启动代理、TUN 或 MCP 服务，不修改系统代理和证书信任。用户仍通过已有的启动、启用按钮使用这些功能。

“仅恢复偏好”是轻量选项；“替换所选类别”用于全新设备或主动恢复旧环境。替换的影响范围在同一预览中说明，不为每一项弹出重复确认。

## 2. 当前配置实际存放位置

下表根据当前源码整理，只描述已有存储。`data_dir` 是内核数据目录：桌面端由 Tauri 的 `app.path().app_data_dir()` 提供，应用标识是 `dev.httpcapture.desktop`；开发服务默认使用仓库下的 `.local/capture`，也可通过第一个命令行参数指定。迁移格式不能把某台设备解析出的绝对数据目录当作目标设备的目录。

### 2.1 内核 SQLite

文件为 `<data_dir>/sessions.db`。配置存入 `settings(key TEXT PRIMARY KEY, value TEXT NOT NULL)`，值为 JSON。

| 当前键 | 当前内容 | 迁移设计 |
| --- | --- | --- |
| `library.v1` | 集合、已保存请求、命名环境、脚本模板、CAS `revision` | 可迁移定义；认证值、变量值、正文和脚本源代码按第 3 节分别处理；导入使用目标设备的新 revision |
| `workspace.v1` | 请求编辑标签、草稿、激活标签、选中记录、父记录关联、gRPC 草稿、已保存请求关联、CAS `revision` | 可选，默认不导出临时工作区；导入清理历史记录关联并重映射请求 ID |
| `interception.v1` | 请求／响应断点开关、来源范围、条件规则 | 导入规则，初始关闭断点开关；命中计数和等待请求不迁移 |
| `blocking.v1` | 阻止开关、作用范围、有 ID 的阻止规则 | 导入规则，初始关闭总开关；保持各条规则的配置状态供预览 |
| `capture-scripts.v1` | 全局抓包脚本、启用状态、脚本变量、模块配置 | 可选源代码；变量值默认排除；导入后禁用 |
| `plugins.v1` | 插件 ID、名称、版本、API 版本、范围、URL 正则、前后置代码、启用状态 | 可选源代码，保留顺序；导入后禁用并校验插件 API 版本 |
| `decryption.bypass.v1` | 不解密的主机列表 | 可迁移，按现有域名校验规则验证 |
| `mcp.server.v1` | 本轮开发中的本地 MCP 服务端配置：启用、端口、发送权限、监听控制权限、敏感头可见性 | 后续迁移可带端口与权限建议；导入时服务关闭，所有权限重新采用目标设备设置，不继承源设备授权 |
| `mcp.server.token.v1` | 本轮开发中生成并保存在 SQLite 的本地 MCP 服务 Bearer Token | 始终排除配置迁移，由目标设备保留或生成自己的 token；完整数据库备份当前会包含此键，不能当作无凭据配置分享 |
| `mcp.clients.v1` | 本轮开发中的外部 MCP 服务定义：ID、名称、HTTP URL 或 stdio 程序与参数、`tokenRequired` 标志 | 迁移无凭据定义；stdio 程序／路径和参数按本机绑定内容重新审阅，初始断开；`tokenRequired` 仅作需补填提示 |

同一 SQLite 还保存 `flows`、`flow_bodies`、`deleted_flows`、`flow_revision`、`flow_changes`，以及导入暂存表 `import_jobs`、`import_rows`。它们是会话、正文、同步与暂存数据，**不属于默认全局配置**。设备迁移不复制整个 `settings` 表，也不导入文件中任意指定的键。

### 2.2 SQLite 之外的内核数据

| 当前位置 | 当前行为 | 迁移设计 |
| --- | --- | --- |
| `<data_dir>/upstream-profiles.json` | 保存代理名称、ID、地址、用户名、认证与记住密码标志；密码字段不序列化 | 默认迁移名称、地址及认证需求；用户名可选。`127.0.0.1`、`localhost` 等地址标记为“请确认本机代理端口”，不假定新设备存在同一个代理 |
| 系统凭据库，服务名 `http-capture.upstream`，条目名为代理 ID | 记住的密码以包含 URL、用户名和密码的凭据对象存储；另有仅在进程内存中保存的密码 | 标准导出不读取、不导出密码或凭据条目；导入后显示需补填密码，不按碰巧相同的 ID 关联目标设备旧凭据 |
| `<data_dir>/certificates/capture-ca.pem` | 当前设备 CA 公共证书 | 默认不迁移；新设备使用自己的 CA。证书单独导出功能继续保留 |
| `<data_dir>/certificates/capture-ca.key` | 当前设备 CA 私钥 | 始终排除全局配置文件；不提供在标准迁移中勾选私钥的选项 |
| `<data_dir>/control.token` | 开发服务每次启动生成的本地控制令牌；Vite 在服务端读取转发 | 始终排除，由目标服务重新生成 |
| `<data_dir>/backups/sessions-<UUID>.sqlite` | 现有数据库备份 | 不打包进配置；导入恢复点与现有完整数据库备份在界面上区分 |
| 状态根目录下的 `http-capture/system-proxy/recovery.json`、`owner.lock` | 系统代理恢复日志和所有权锁；根目录依次取 `LOCALAPPDATA`、`XDG_STATE_HOME`，否则 `$HOME/.local/state` | 始终排除；原机恢复信息只能用于原机，不能在另一台设备回放 |

当前选中的全局上游代理仅存在 `UpstreamState.config` 内存中，未写入代理列表文件；TUN 的应用列表、QUIC 开关与运行状态目前也属于运行时配置，没有独立持久化设置键。不能声称它们现已随重启恢复。后续可持久化为迁移用的“配置意图”，导入后仍不启动。

本轮 MCP 外部客户端的 Bearer Token 仅保存在 `ClientManager` 的会话内存中，不写入 `mcp.clients.v1` 或系统凭据库；重启后 `hasToken=false`，需要重新填写。配置保存本身不连接服务，手动连接后才读取目录，工具需用户手动调用。这是当前开发实现边界，不能把客户端 token 称为已经持久化或可加密迁移。

TUN 辅助进程路径由当前可执行文件位置或开发目录 `.local/tun` 解析；`HTTP_CAPTURE_HTTPCLOAK`、`HTTP_CAPTURE_TUN_DEBUG_LOG` 等环境变量、辅助程序路径、机器上的应用绝对路径和网卡／路由状态不默认迁移。应用名称可以作为待确认建议，绝对路径在新设备重新选择。

### 2.3 前端 localStorage

下列值保存在当前浏览器或 WebView 的 origin 内，而不是 `sessions.db`。`localhost:1420` 与 `127.0.0.1:1420` 的开发预览具有不同存储，桌面 WebView 也不能靠复制浏览器 localStorage 自动恢复。只迁移白名单键，经类型校验后映射到统一迁移模型。

| 当前键 | 内容与处理 |
| --- | --- |
| `http-capture.theme` | 主题；当前支持 light、dark、cyberpunk、arctic、dusk、paper、sonar、forge、matrix、sakura；目标不支持时预览并回退 |
| `http-capture.language` | `zh-CN`／`en`／`system` 语言偏好 |
| `http-capture.zoom` | 界面缩放；当前有效档位为 75、90、100、110、125、150 |
| `http-capture.listener.v1` | `{host, port}` 监听偏好；端口当前校验范围为 1024–65535；新机重新检查 IP 是否可用和端口占用，不自动监听 |
| `http-capture.body-editor.auto-format-paste.v1` | 粘贴后自动格式化开关 |
| `http-capture.capture.columns.v1` | 流量列表显示列；仅保留目标版本支持的列 ID |
| `http-capture.capture.column-widths` | 列宽；按目标版本允许的范围校验 |
| `http-capture.capture.id-sort` | ID 升／降序 |
| `http-capture.layout.inspector-direction` | 请求响应详情左右／上下布局 |
| `http-capture.layout.composer-columns` | 发送页请求／响应分隔比例 |
| `http-capture.layout.capture-list` | 抓包列表／详情分隔比例 |
| `http-capture.layout.capture-messages-row`、`http-capture.layout.capture-messages-column` | 详情左右／上下模式各自的分隔比例 |
| `http-capture.code-target` | 上次选择的导出代码语言／包组合 |
| `http-capture.clienthello-templates.v1` | 自定义 ClientHello 模板名称和十六进制内容；验证格式与目标能力，不复制 TLS 会话密钥 |
| `http-capture.grpc.proto.v1` | 用户输入的 proto 文本数组；可选迁移，重新解析；不沿用源设备文件路径 |
| `http-capture.request-modes` | 以编辑器 ID 为键的 HTTP／gRPC／WebSocket 模式；仅迁移工作区时一起重映射，不携带无主记录 |
| `http-capture.updater.skippedVersion`、`http-capture.updater.skippedVersion.preview` | 本机曾跳过的更新版本；不迁移，避免在新设备继续隐藏升级提示 |

其他临时组件状态、剪贴板、WebView 浏览数据、缓存、浏览器登录 Cookie、系统凭据库、下载路径不纳入迁移。不能用“复制所有 `http-capture.*`”实现导出。

源码依据：[store.rs](../crates/capture-core/src/store.rs)、[upstream.rs](../crates/capture-core/src/upstream.rs)、[lib.rs](../crates/capture-core/src/lib.rs)、[ca.rs](../crates/capture-core/src/ca.rs)、[system_proxy.rs](../crates/capture-core/src/system_proxy.rs)、[tun.rs](../crates/capture-core/src/tun.rs)、[桌面启动](../apps/desktop/src-tauri/src/main.rs)、[前端偏好](../apps/frontend/src/listenerPreferences.ts)。

## 3. 默认范围与敏感内容

推荐首版先交付可审阅的普通 JSON“标准配置”。标准配置默认包含界面偏好、监听偏好、代理连接定义、解密绕过列表、断点／阻止规则定义、集合结构与请求定义。proto、自定义 TLS 模板、临时工作区、插件代码和脚本代码在高级选项中分别选择。

请求、规则、变量、脚本与 proto 都可能包含业务数据。不能仅按字段名称扫描后宣称“已去除全部秘密”。采用下列明确边界：

- 专用的密码、控制令牌、私钥、MCP 授权材料不进入标准包。代理认证用户名默认不包含，保留“需要认证”的提示。
- 环境变量与脚本变量默认只带名称，不带值；缺失值写进迁移包的 `requiredInputs` 元数据。导入后显示“待补填”，不把占位字符串当作真实变量值发送。
- 请求默认保留方法、URL 结构、协议／TLS 选项和请求头名称／启停状态。URL userinfo、fragment、查询值、请求头值、HTTP 正文与 gRPC JSON 草稿内容默认排除；界面说明这些值需要补填。模板引用 `{{name}}` 可保留，但对应变量若无值，仍需补填。
- 用户可在明文高级选项中审阅并保留确定为普通数据的请求字段、规则条件和模板文本；界面明确普通 JSON 不加密。不得通过这一选项重新包含专用密码、token、私钥字段。
- 插件和脚本源代码可能硬编码凭据，代码导出默认不选；勾选后预览实际代码及明文性质。无论选择情况，导入的可执行配置初始均禁用。
- 规则条件和名称也可能含内部地址、请求头匹配值或业务标识，导出摘要须列出这些类别并可逐项排除；不承诺仅靠自动检测达到匿名化。
- 导入的请求若有 `requiredInputs`，发送入口应先展示待补填字段；导出代码也不能悄悄丢失这些提示。该状态是新增迁移元数据，当前请求模型尚不具备，需要实现时补齐。

后续增加“完整迁移（加密）”模式，解决真实请求正文、Cookie、Authorization、token、变量值与可选代理密码的跨设备恢复。它需要单独实现密码输入、经过审查的认证加密格式、带盐与版本参数的口令派生、完整性验证、错误口令行为、内存与日志清理和系统凭据库重新写入。算法、参数、库和文件格式届时锁定并测试；**当前没有此能力，不能在 UI 或文档中称为已加密**。

加密文件的恢复口令由用户保存，不放入同一个包，也不写到日志或普通配置。即使有加密模式，CA 私钥、系统代理恢复日志、现有本地控制 token、MCP 会话／OAuth 授权也不迁移。若未来要支持企业共用 CA，应作为独立证书管理需求设计。

## 4. 迁移文件模型与兼容性

建议外层模型如下。它是结构示意，不是现已可导入的文件；`sections` 内的完整类型须在实现时形成 JSON Schema 和 Rust／TypeScript 共享契约。

```json
{
  "format": "http-capture-config",
  "schemaVersion": 1,
  "exportId": "a-new-uuid-for-this-export",
  "exportedAt": "2026-10-19T00:00:00Z",
  "source": { "appVersion": "0.1.19", "platform": "windows" },
  "requiredFeatures": [],
  "sections": {
    "preferences": { "version": 1, "data": {} },
    "upstreamProfiles": { "version": 1, "data": [] },
    "library": { "version": 1, "data": {} }
  },
  "requiredInputs": [],
  "excluded": ["credentials", "caPrivateKey", "sessions", "machinePaths"]
}
```

规则：

- `schemaVersion` 是迁移协议版本，与应用版本及当前存储键 `.v1` 分开。应用版本只作来源说明，不能据此跳过字段验证。
- 精确验证 `format`、整数版本、结构、字段类型、字符串／数组规模、ID 唯一性、引用完整性、URL／正则／Base64／proto 格式及现有业务限制。拒绝重复 JSON 键、原型污染键、非有限数值和任意存储键／路径。设置清晰的文件字节数与项目数上限，超限报错且不提交；上限在实现与实际大集合测量后确定，不把当前旧文档的大小限制直接套用。
- 每个类别单独版本化。缺少的可选类别代表“不处理该类别”，不代表清空；未知且非必需类别在预览中列出并跳过。未知必需能力或较新的必需版本阻止提交并提示升级，不静默降级。
- 仅通过已注册的迁移步骤升级旧 schema；先在临时模型上转换与验证，原文件不修改。不能反序列化失败后转用宽松的任意 JSON 写库。
- 不将来源 `revision` 写成目标 CAS 版本。提交使用导入预览时目标的配置修订与内容摘要；目标在预览后发生变化时重新预览，保留已选选项。
- 文件摘要可用于识别重复导入和损坏检测，但不能把自带的哈希当作可信签名。普通 JSON 来自不可信文件，任何代码和说明都只作为数据处理。
- 导出不记录源设备用户名、主机名、完整数据目录或本机进程列表；平台字段只用于给出兼容提示。

## 5. 合并、替换和引用重映射

合并默认为“保留本机项目，导入冲突项为副本”。同一 `exportId` 重复导入时利用来源项目映射和内容摘要保持幂等：相同内容跳过，来源或本机内容已改变则在预览中列为冲突，不无条件创建重复项。

| 类别 | 合并规则 |
| --- | --- |
| 主题、语言、缩放、列、布局等标量偏好 | 默认保留当前值，用户可在预览选择采用文件中的值；新设备未设置时采用文件值 |
| 集合、请求、环境、脚本模板 | 为新项目分配本机 ID，维护统一映射；同名但内容不同默认加“（导入）”后缀，不按名称覆盖 |
| 上游代理 | 新建本机 ID，重映射请求 `upstreamProfileId`；无导入代理或需补填凭据时清晰标记，不误用本机同 ID 代理 |
| 插件 | ID 影响插件身份；同 ID 同内容跳过，不同内容默认保留本机并在预览选择替换或跳过，不能为逃避冲突任意改插件 ID；导入副本保持禁用 |
| 断点规则 | 保持源文件顺序，先预演与本机规则合并后的现有限制；当前断点规则没有独立 ID，按规范化内容匹配，排除规则及其优先行为不能改变 |
| 阻止规则 | 新建冲突 ID 并保留排序，重新校验总数／模式／方法；默认关闭总开关 |
| 全局抓包脚本 | 单份配置不能盲目拼接代码；有冲突时保留本机，预览可选择替换。所选代码初始禁用 |
| 工作区 | 可选导入到新增标签，重映射编辑器 ID、激活标签、保存请求关联及 request-modes；`selected` 与 `parentId` 指向历史流量时清除 |
| proto、ClientHello 模板 | 按规范化内容去重，同名不同内容生成可辨识名称；先验证目标引擎与解析能力 |

“替换所选类别”只替换用户选中的类别，不删除其他类别和会话历史。替换集合或代理时，必须同时预览依赖项：例如保留的草稿仍引用将被删除的请求或代理，需要用户选择纳入映射、保留关联对象或清除并标记待补填；不允许留下静默悬空引用。

导入顺序、规则顺序、插件执行顺序和重复请求头顺序必须显式保留。不能为了去重把有序列表转换成无序 map，也不能把同名请求头合并后声称请求完全恢复。

## 6. 原子提交、失败保护与恢复

当前配置横跨 SQLite、代理 JSON、系统凭据库和 localStorage，逐次调用已有保存接口无法保证全局原子性。导入器不能使用“前端循环保存，失败就再写回去”来宣称回滚完整。

建议实现前先统一可迁移配置的权威提交边界：

1. 可迁移的代理元数据和 UI 偏好进入 SQLite 管理的配置快照／修订。对已有 `upstream-profiles.json` 和上述 localStorage 做一次性兼容读取与升级；这些路径随后只作可恢复的兼容投影或缓存，不能继续与权威数据双向抢写。系统凭据库仍是本机独立存储，标准导入不修改它。
2. 用同一配置写入协调器处理普通设置修改、集合／工作区保存及迁移，建立全局修订或等价 CAS 边界。导出在该边界取一致快照；导入预览保存其目标修订。
3. 提交前完成全部解析、业务校验、ID 重映射、依赖检查以及内存配置构造。活跃监听、TUN、拦截等待项、正在运行的请求／脚本或其他配置写入尚未结束时，不强行半途改配置；保留导入预览并提示停止或稍后重试。不能自动丢弃用户正在编辑的草稿。
4. 通过单个 SQLite 事务保存所有选中类别、更新修订、保存导入前可恢复快照及完成记录。任何校验、磁盘不足、锁冲突或写入错误使事务整体回滚；旧配置和抓包历史均不变。
5. 成功提交后发布已经准备好的内存配置快照，再刷新前端视图与 localStorage 投影。投影失败时以数据库为准重建，界面显示“配置已导入，界面缓存待恢复”，不能误报“导入失败，所有内容未改变”。下次启动优先恢复投影，再允许继续编辑。
6. 若进程在提交前退出，SQLite 保留旧快照；提交后退出，重启从新权威快照完整重建。恢复记录包含提交阶段与版本，不保存秘密。不能出现 DB 已替换而代理仍从旧 JSON 恢复的分裂状态。

上述收拢是设计前置工作，当前尚不存在这套配置快照与全局修订机制。若首版暂不完成，必须限制首版支持的类别到同一事务边界，并在界面称为部分配置导入，不能承诺完整全局回滚。

导入前恢复点只包含被替换的可迁移配置；按本机权限限制访问，不上传。保留最近若干次并允许用户清理；数量与占用上限在实现时确定。用户点击“恢复上次配置”仍经预览和同一事务恢复，不复活会话、系统代理、TUN 或旧授权。恢复点失败时不开始配置替换。

未来加密迁移如果可写入系统凭据库，需要额外设计凭据暂存、失败恢复与提交后清理。它不属于上述无凭据单事务首版；不能把数据库事务覆盖不到的系统凭据写入称为原子提交。

## 7. 与 MCP 的衔接

用户已要求两种 MCP 方向，优先让 AI 操作抓包工具。本轮开发已经引入第 2 节列出的服务端／客户端持久化键，MCP 配置迁移仍未实现。后续 MCP 新增存储或凭据方式时，须同步更新迁移白名单及排除项；不能仅因新的存储键以 `mcp.` 开头就自动打包。

迁移模型预留可选 `mcp` 类别与独立版本，建议只迁移服务器／客户端的显示名称、协议种类、工具范围建议、无凭据端点和连接结构。以下内容不能从另一设备直接恢复为有效权限：

- 本地服务 token、API key、OAuth token／refresh token、会话 ID、已连接状态、授权客户端身份与本机权限授予记录。
- 远程请求中的 Authorization／Cookie、自定义认证头值与环境变量中的秘密。
- 需要运行的本机命令、可执行文件绝对路径、工作目录和本机环境变量值。可作为未解析的待配置说明显示，不自动执行，也不从文件安装软件。

导入的 MCP 连接默认断开，本地服务默认关闭。源设备“允许某 AI 客户端修改请求／放行断点”等授权不迁移；在目标设备沿用 MCP 本身设计的连接与授权流程。普通配置导入不额外制造无关审批，也不因为文件里声称已授权而绕过现有控制。

后续 MCP 若提供配置读取或迁移工具，应调用同一迁移服务和白名单模型；不暴露“按路径读取任意数据目录”“原样导出 settings 或凭据库”的通用工具。配置文件中的文字、插件说明和服务元数据不能当作 AI 指令。

## 8. 实施阶段与验收记录

建议分两次开发：

1. 标准 JSON 迁移：统一配置权威存储、schema／预检、导出、合并／替换预览、原子提交／恢复点、前端刷新和待补填提示。MCP 稳定后把其无凭据连接结构加入白名单。
2. 加密完整迁移：敏感项分类、加密容器与密钥处理、系统凭据库重新写入及其恢复协议。明确通过测试前不展示为已支持。

自动化检查至少覆盖：旧版本升级与未知新版本拒绝、恶意／损坏 JSON、遗漏类别不清空、大小与业务上限、敏感项标准包排除、ID／引用重映射、顺序保持、重复导入幂等、CAS 冲突、全类别写入失败注入、提交前后进程中断恢复、localStorage 投影失败、恢复点回滚，以及导入期间绝不发送网络请求／执行脚本／启动 MCP。

后续手工验收集中记录，等用户有时间完成：

- Windows 到 Windows、Windows 到 macOS／Linux 的配置迁移；旧版本文件到新版本的兼容性。
- 原生文件保存／打开、权限不足、磁盘不足、取消和损坏文件提示。
- 更换屏幕分辨率／缩放后布局有效；无效监听 IP／已占用端口有明确提示且不自动启用。
- 本机代理 7897 不存在、代理密码未补填、不同系统凭据库锁定时不误用连接。
- 导入前后集合、请求头顺序、禁用头、gRPC／TLS 模板、插件和脚本配置符合预览；填好缺失值前不误发送请求。
- 目标设备独立安装 CA、启用系统代理／TUN、连接 MCP；原设备 CA、系统代理恢复日志和授权均未被迁移文件改变。
- 合并、替换和“恢复上次配置”的结果与预览一致；已有抓包历史保持不变。

这一步仅完成设计记录。当前用户仍可分别导出集合、规则和会话，或在停机条件下恢复 SQLite 备份；完整迁移入口、统一快照、原子导入和加密模式均等待后续实现。

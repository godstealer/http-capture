# 待手工验收清单（2026-10-18）

按用户要求，先完成开发、自动检查和正式发布，手工验收留待有时间时执行。以下均为待验收，不能据浏览器示例或编译通过改为已通过。

| 状态 | 检查项 | 操作与预期 |
| --- | --- | --- |
| [ ] | 新请求保存 | 新建 HTTP 请求，填地址/头部/正文，点击右上「保存请求」。首次无需先建集合；保存后关闭标签，在左侧「集合」重新打开，应恢复原内容。 |
| [ ] | 更新与另存为 | 修改已保存请求并 Ctrl+S，集合中仍只有原记录且内容更新。另存为创建第二条。重启软件后再保存，仍更新关联记录。 |
| [ ] | 保存失败 | 内核不可用时保存不能显示成功；编辑内容保留。恢复内核后重试。两窗口修改集合时冲突提示应保护本地内容。 |
| [ ] | gRPC 集合 | 填方法及未完成 JSON，保存、关闭并从集合打开；模式、方法和原始 JSON 应恢复。定义文件仍通过 Protobuf 定义管理保存。 |
| [ ] | 代码导出 | 在请求页点击「导出代码」，切语言和库；方法、地址、启用头部、正文应对应当前请求。复制到编辑器与下载文件应一致，扩展名正确。 |
| [ ] | 目标库运行 | 自选需要的语言/库，安装提示中的依赖，向自己控制的回显服务运行代码；检查 Unicode/二进制/JSON/form/multipart 字节。浏览器 CORS 或受限字段应按提示判断，不能与服务端 SDK 等同。 |
| [ ] | 导出边界 | 禁用头部不导出；字典库提示同名字段合并。带正文的 GET/HEAD 在不支持的库中明确提示，换用支持的库后字节保留。导出不执行脚本、不默认接入抓包代理。 |
| [ ] | 缩放与外观 | 桌面 75%～150% 下检查鼠标选字、右键、分栏、保存/导出弹窗和底部按钮；十套主题的文字、选中与错误提示可读。 |
| [ ] | 正文与剪贴板 | 请求头全部/单行复制；文本/JSON、URL 编码、同名 multipart 字段与文件、二进制；CodeMirror 粘贴格式化开关及 Undo/Redo。 |
| [ ] | 设置恢复 | 改监听 IP/端口后重启，应恢复有效值；非法/占用端口不能覆盖。设置切页保留输入和滚动位置，各页保存/执行操作符合提示。 |
| [ ] | 流量来源 | Windows 本机两应用分别发请求，应展示各自进程；远端客户端只显示可确认的地址。TUN 不误认 helper，macOS 未支持项与导入来源应明确标注。Linux 需目标机器验证。 |
| [ ] | 正式安装升级 | 分别验证 Windows 安装包/便携版、macOS Intel/Apple Silicon、Linux AppImage/Deb 的安装、启动、旧版应用内更新、安装重启及版本显示。 |
| [ ] | 系统集成 | 目标平台 CA 安装/信任/卸载、系统代理开启/恢复、异常退出恢复、TUN 权限/路由和 QUIC 接管继续单独验收。 |
| [ ] | 大文件与长连接 | 大请求/响应、并发、取消与慢流控的内存峰值；SSE、WebSocket、gRPC 和真实业务兼容仍按路线图检查。不能因本轮基本保存与导出通过而视为协议验收完成。 |

记录问题时附平台、版本、步骤、预期/实际结果即可；分享抓包或导出代码前自行去除 Cookie、Authorization、请求正文等凭据。

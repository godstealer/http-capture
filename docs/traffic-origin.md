# 流量来源

本文说明当前流量来源的识别方式与支持范围。安装包实际范围与发布状态见[更新说明](release-2026-10-20.md)；实现和自动化覆盖不代表所有平台实机验收完成。

## 查看方式

抓包列表新增「来源应用」默认列；已有自定义列偏好的用户保留原配置，可在「列设置」勾选来源应用、客户端地址、流量入口。过滤框支持应用名、PID、进程路径、客户端地址和入口，大小写不敏感。

选中请求后，在请求「总览 → 流量来源」查看应用、PID、进程路径、客户端地址、入口和识别说明。应用信息来自操作系统的连接归属，不根据 User-Agent 或自定义请求头猜测。多进程浏览器通常显示实际持有网络连接的进程，不提供浏览器标签页归属。

## 支持范围

| 入口 / 平台 | 当前行为 | 验证边界 |
| --- | --- | --- |
| Windows 本机显式 TCP 代理 | 按客户端完整 IP/端口四元组查询进程，显示 PID、可执行文件名和路径；支持 IPv4/IPv6 | 独立客户端进程的 IPv4/IPv6 实际归属测试通过 |
| Linux 本机显式 TCP 代理 | 有界读取 `/proc` TCP 表和进程 FD，复查 socket inode、进程启动时间及连接；受权限和命名空间影响 | 解析/边界测试通过；真实 Linux PID 识别尚未实机验证；scoped IPv6 缺少 zone 信息时不归属 |
| macOS 本机显式代理 | 显示客户端地址、入口；进程识别明确提示平台暂不支持 | 原生进程识别待实现 |
| 局域网其他设备 | 显示客户端 IP 和端口，标记远程客户端 | 代理端无法直接查询远端进程；需客户端配合才能补充应用信息 |
| TUN TCP / 重定向 QUIC | 标记 TUN 入口，原始地址和进程暂未提供 | 不把本机辅助进程及其 loopback 地址当作原始客户端；helper 元数据链路待补 |
| 显式 QUIC 反向入口 | 显示连接地址和 QUIC 反向入口；说明该入口暂不支持应用识别 | 未实现 UDP socket 进程归属 |
| 手动 HTTP / gRPC / WebSocket | 明确显示本应用手动发送 | 重放不继承父请求的应用、PID 或客户端地址 |

客户端地址表示直接连接抓包入口的一方。经过其他本地代理时，识别到的可能是该代理进程；不能由此推断更上游的原始应用。快速关闭、权限不足、查询超时或系统状态变化时显示未识别，抓包继续执行。

## 保存与并发

Flow 新增可选 `trafficOrigin`，含 `entry`、`clientAddress`、`process`（`pid`、`name`、`path`）和 `processStatus`。旧记录缺少字段时显示未记录，无须迁移 SQLite。会话 JSON 和数据库保留来源；导入记录明确标注文件记录且未经本机验证。普通 HAR 没有这些本机进程字段。

连接级上下文传入 HTTP/1、HTTP/2 多路流、WebSocket、SSE、阻止和解密例外隧道记录。HTTP/2 子任务显式复制自己的连接来源，重放强制不带捕获来源。

进程识别最多同时运行四个阻塞查询。页面一次打开较多新连接时，后续识别请求会限时等待空位；**一秒预算包含排队和查询**，超过预算便显示未识别并继续处理连接。拿到空位后才创建阻塞任务，因此不会为每条连接预先堆积阻塞线程。这里的四项并发只限制来源识别工作，不表示代理只支持四条连接。

取消或超时不会中断已经进入操作系统的阻塞查询；它持有额度直到实际结束，避免旧任务未结束又无限追加新任务。等候期间取消的请求不会启动查询。不缓存 PID/端口归属，连接快照变化、权限不足、排队或查询超时均可能得到未识别；未识别不等于流量没有来源，也不会依据请求头补猜应用名称。

本机地址判断和进程查询各有自己的受限工作预算，不是对完整 HTTP 请求的统一一秒超时。来源元数据按新连接识别，不保证补认已经显示为未知的历史记录。后台任务与局部正文范围读取的改进也不代表所有发送、保存和前端路径都已实现恒定内存。

## 验证

- 自动化覆盖 Windows IPv4/IPv6 独立子进程归属、完整客户端方向四元组、地址/端口/IPv6 scope、损坏和歧义表、Linux 解析边界，以及来源查询繁忙时的限时等待、取消和超时后额度保持。
- 真实本地 HTTP 双连接来源隔离、HTTP/2 并发流、WebSocket Upgrade/帧更新、保存后重开、重放不继承来源及 TUN bridge 不误认 helper 的四项集成测试通过。
- 完整 `capture-core --no-default-features` 回归通过；真实系统凭据库及可选 TUN helper 的测试仍按已有条件忽略。服务端和 Windows 桌面编译检查通过。
- 前端来源格式、导入/重放语义、恶意内容和控制字符、无效 PID、列偏好、真实列表过滤、中英文及完整前端回归通过，生产构建通过。隔离浏览器示例已检查来源列、详情、搜索和主题配色，不连接用户真实抓包数据库。

TUN 原始进程/地址传递、macOS 进程识别及 UDP/QUIC 进程识别仍未实现。Linux 实机与权限场景、浏览器集中创建连接时的来源覆盖率、长时间并发/取消/停止监听，以及真实安装包各主题和缩放下的来源展示继续待实机验收。少量自动化连接归属成功不能证明所有浏览器标签页或所有连接都会识别成功。

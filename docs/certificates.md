# 证书管理

入口：顶部 **设置 → 证书管理**。需要连接新版内核；浏览器开发前端本身不保存证书私钥。

## 三种用途

| 分类 | 导入内容 | 用途与生效方式 |
| --- | --- | --- |
| 抓包 CA | CA 公钥证书、匹配的私钥 | 用自己的 CA 签发 HTTPS 抓包证书。导入后点击“切换为此 CA”并确认，重启整个内核进程后使用。 |
| 客户端证书 | 客户端证书链、匹配的私钥、精确域名/IP 和端口 | 用于需要双向 TLS（mTLS）的服务器。导入默认停用，启用后用于匹配目标的新连接。 |
| 服务器信任 | CA 公钥证书、可选精确域名/IP 和端口 | 为内部、自签或私有 CA 服务扩展上游信任。导入默认停用，启用后用于新连接。 |

“系统与证书”页原有的导出、安装/移除本机信任功能仍保留。**导入证书不会自动安装系统信任。** 私钥文件只留在管理证书的一端；给浏览器、手机或其他客户端安装信任时，只传公钥证书。

## 导入步骤

1. 选择证书用途，填写容易识别的名称。
2. 选择 PEM/DER 公钥证书文件，或包含身份和私钥的 P12/PFX 文件。单独选择 PEM/DER 时，抓包 CA 和客户端身份还需要选择配套私钥文件。加密 PEM 私钥或 P12/PFX 会出现密码输入框，密码只用于本次导入。
3. 客户端身份填写准确的目标域名及端口，例如 `api.example.com`、`443`，不填写 `https://`、路径或通配符。
4. 点击“导入并保存”。工具校验证书有效期、证书用途、CA 签发权限及证书与私钥匹配关系；失败时不修改已保存配置。
5. 核对列表里的名称、有效期、签发者和 SHA-256 指纹，再按需要启用或切换。

客户端身份只匹配同一域名/IP 和端口，不匹配子域名；同一目标不能同时启用两个身份。服务器信任留空域名时作用于所有目标（忽略端口），填写域名时只作用于该域名和端口。自定义信任不会关闭正常的证书链、有效期及域名验证。

## 抓包 CA 切换与恢复

切换 CA 需要重启整个桌面应用或开发内核服务，单纯停止/开始捕获不会重新加载 CA。界面会显示“重启后使用”。重启后从“系统与证书”导出当前 CA 公钥，并在抓包客户端信任它。

工具保留原来的内置 CA，可以点击“内置抓包 CA → 切换为此 CA”，确认并重启后恢复。正在使用或下次启动选中的 CA 不允许删除；切换并重启后才能删除原自定义项。工具不会自动删除系统、浏览器或其他设备中的旧 CA 信任。

## 文件与发送引擎支持

- 支持 PEM 证书链、单张 DER 证书、未加密或加密 PEM 私钥，以及 P12/PFX 容器。P12/PFX 中的证书与私钥须匹配；服务器信任用途不能导入私钥。证书链按“身份/签发 CA 在前，中间 CA、根 CA 在后”排列。CA 文件中的每张证书都必须具有 CA 用途。
- 单个证书/私钥文件最多 1 MiB，每个文件最多 16 张证书，最多保存 64 个配置。
- 导入时解锁 P12/PFX 或加密 PEM 私钥，并在内存中规范化为未加密的私钥供已有 TLS 引擎使用；解锁密码不会写入证书库、请求记录或配置导出。规范化私钥按下文的本机证书库存储方式保护。
- Native、Auto、H2、H3、gRPC、WebSocket 和启用 browser-replay 的 wreq 已接入上游信任与客户端身份。
- 本地未发布增量已让 httpcloak helper 支持自定义上游 CA 和客户端身份，H1/H2 本地双向 TLS 握手回归通过。旧 helper 缺少相应能力时会在发送前明确报错，不忽略配置。安装版及真实业务证书仍待验收。

## 存储和迁移

证书库独立存于内核数据目录的 `certificate-manager/identities.v1`。Windows 使用当前用户的 DPAPI 加密；macOS/Linux 使用权限受限的本机文件（目录 0700、证书库 0600），不宣称磁盘加密。

私钥不写入抓包记录、请求草稿、SQLite 或全局配置导出。界面和 API 列表仅返回名称、用途、目标、状态和公钥元数据，不提供私钥读回接口。切换分类、关闭证书页、断开内核及成功导入会清除前端暂存的文件内容和密码。

因此，迁移设备后需要从原始文件重新导入证书，不要直接复制 Windows 加密证书库给另一个用户。多个窗口/进程同时编辑时采用版本检查和文件锁，冲突会要求刷新，避免覆盖其他窗口的修改。

## 验证范围

本轮提供独立本地 TLS/mTLS、HTTP/2、HTTP/3、代理 CONNECT、API 认证/配置冲突、私钥隔离及前端交互回归。实际安装版的系统信任、原生文件选择、macOS/Linux 权限与真实业务服务验收仍需在对应环境操作，不由本地 Windows 自动化测试代替。

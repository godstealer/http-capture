# 自动响应重写

状态：自动响应重写已随 [0.1.33](https://github.com/godstealer/http-capture/releases/tag/build-a59befecdc1c) 正式发布，构建、原生更新测试与公开附件核验见[本轮说明](release-2026-10-20-body-preview.md)。0.1.31 的响应替换入口是手动响应断点；0.1.33 增加自动规则并接入按需正文。原 0.1.32 候选未发布，其功能已合并进本版；实际安装与业务流程仍按文末清单验收。

## 从哪里开始

连接内核后，打开侧栏 **响应重写**，选择 **替换整份响应** 或 **修改部分内容**。也可以在已收到响应的抓包记录上右键，选择 **自动替换响应 / 自动修改响应**；详情顶部也有同名按钮。

从记录创建的模板匹配该条完整 URL 和请求方法，包含查询参数。模板默认禁用，先检查匹配内容和数据，再保存；它不会修改已经收到的历史响应。WebSocket 和 CONNECT 直通不使用此入口。

1. 填写匹配方式、内容和可选方法；方法留空表示任意方法。可选 URL 包含、URL 正则或域名精确匹配。域名不含协议、端口、路径或通配符。
2. 按需选择 **仅抓包流量 / 仅手动请求 / 全部来源**。范围覆盖普通 HTTP 请求；不会因此启动监听或发送请求。
3. 填好替换内容或修改项，点击 **保存并启用此规则**，同时打开总开关和当前规则。其他已启用规则仍按列表顺序参与匹配。
4. 重新产生匹配请求，检查返回内容、记录中的转发说明和原始响应。需要关闭时，取消总开关并点击 **保存全部规则**。

**保存全部规则**只保存当前开关和编辑内容，不会自动打开关闭的开关。新建、复制、排序、删除、读入文件和编辑都先改变草稿，保存后才影响后续请求。保存成功或重启会重置命中计数，规则定义和开关会保留。

## 两种模式

| 模式 | 用法 |
| --- | --- |
| 替换整份响应 | 指定 200–599 状态码、有序响应头和完整正文。正文可编辑 UTF-8 文本、Base64，或从本地文件读入；支持二进制内容 |
| 修改部分内容 | 保持状态码，按修改项顺序查找替换 UTF-8 正文，或设置、查找替换、删除指定响应头；支持普通文本或正则 |

响应头保留重复字段及相对顺序，`Set-Cookie` 不会自动合并。字段名匹配不区分大小写。“仅首个匹配”对响应头表示第一条同名字段，其中的文本替换也只改首次匹配；选择“全部匹配”会处理全部同名字段和其中的全部文本匹配。

正则使用 Rust 语法，不支持环视和反向引用；替换内容支持 `$1`、`${name}` 分组和 `$$`。普通文本替换中的 `$` 按字面处理。URL 包含区分大小写，域名和请求方法不区分大小写。

修改 UTF-8 替换正文或读入文件时，正文或相关元数据发生变化才会清除旧内容编码、长度和失效校验头（含 Content-Digest、Repr-Digest）；原样重复输入会保留原头。直接编辑 Base64 时保留内容编码，需确保字节与响应头一致。`Content-Length`、传输编码、连接及其他逐跳字段由内核处理，局部修改不能直接设置这些字段。

## 执行顺序与出错处理

**上游仍会收到请求。** 此功能在收到正常上游响应后才执行；上游失败不会变成预设的成功响应。需要不访问上游就返回内容时，使用请求阶段的手动替换，而不是自动响应重写。

相关顺序是：上游发送 → 响应后插件/脚本 → 自动响应重写 → 手动响应断点。全部启用且匹配的自动规则按列表顺序执行，后一条看到前一条的结果；这与故障模拟只使用第一条匹配规则不同。

每条规则作为一次完整修改提交。如果某个修改项解压失败、编码不支持、产生非法头值或超过限制，**丢弃该条规则的全部修改，保留该规则执行前的响应**，记录原因，再继续后续规则。先前成功规则的结果保留，不会自动退回最初上游响应。

记录的 `originalResponse` 保留最早的原始响应，不会被后一条规则或手动响应断点覆盖。替换后的协议、TLS 和实际发送请求头信息仍来自真实上游连接。若同时启用了手动响应断点，队列里看到的是自动修改后的响应，可以继续修改或原样放行；关闭自动重写不会关闭手动断点。

## 大小、编码与协议边界

| 情况 | 当前处理 |
| --- | --- |
| 配置规模 | 最多 32 条规则，每条最多 32 个修改项；配置最多 16 MiB |
| 正文大小 | 整份替换最多 8 MiB 原始字节；文本局部修改的编码正文、每步解压结果和替换结果也受 8 MiB 限制。不是全链路大文件编辑功能 |
| 响应头 | 最多 256 项、64 KiB，包含程序补充的长度等字段；非法名称、换行、控制字符及非 Latin-1 头值会拒绝 |
| 压缩正文局部修改 | 支持 gzip、deflate（zlib 或旧 raw 格式）、br、zstd，按编码逆序受限解压；实际改变后移除旧编码、ETag/摘要等失效头及 trailers，重算长度。没有文本变化时保留原压缩字节 |
| 文本类型 | 必须是有效 UTF-8 且不含 NUL；显式非 UTF-8 字符集、非 SVG 图片、音视频、字体、PDF 和声明为二进制的正文不做文本修改。整份替换可用文件/Base64 |
| HEAD、204、205、304 | 不做正文局部修改；整份替换不发送实体字节，按状态修正长度。仅改头时保留合法的 HEAD/304 表示长度，204 不带长度，205 为零长度 |
| 206 | 不做局部正文修改，避免破坏分段范围含义；可单独修改允许的响应头，或自行配置完整替换 |
| WebSocket、SSE、gRPC 流 | 自动重写跳过这些响应，保留原内容并记录原因；不提供流式逐帧修改 |

仅修改响应头不需要解压正文，也不受文本格式限制，但流式响应仍按上表跳过。失败原因在记录说明中显示；不支持的正文不会被截成有限前缀再当作完整响应。

## 保存冲突与设备迁移

保存会比较读取配置时的版本。其他窗口或内核已修改规则时，旧版本会被拒绝，保留当前草稿；先保留需要的内容，再 **取消修改 → 重新加载**。断线重连不会覆盖未保存草稿，也不会自动解除版本冲突。

[全局配置迁移](config-migration.md)新增 **响应重写规则** 类别。规则可能含响应正文、头值或匹配凭据，因此只有导出时勾选 **包含请求内容和变量值** 才带出这些规则；默认导出的该类规则列表为空。标准 JSON 不加密，分享前检查内容。导出、导入都会关闭总开关和各条规则，导入后按提示重启，再审阅范围并手动启用。

旧包没有此类别时仍可导入；导入首版按所选类别替换，不合并规则。当前 MCP 断点工具继续操作手动拦截队列，未新增自动响应重写专用 MCP 工具。

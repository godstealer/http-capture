# HTTP Capture 桌面版更新说明（2026-11-15）

本版包含 0.1.78 之后的局域网协同抓包增量。正式版本号采用同一源码的 GitHub Check 编号，四平台构建、更新签名及公开附件核验完成后公开。

## 更新内容

- PC 配对状态和远程流量详情增加“设备名称（自报）”，可在来源提示与搜索中查看 Android 制造商/型号，便于区分测试设备。需要支持名称上报的 Android 测试客户端；旧客户端仍可继续配对，但不显示名称。
- 设备名称通过已认证、固定 PC 身份的 TLS 会话上报，独立于应用和进程信息。名称限制长度并过滤控制字符；断开、重新配对和会话到期后不再显示旧名称，手动重放不继承原设备标签。
- 保持 v1 二维码兼容。新版 Android 测试客户端连接旧 PC 时，只有额外确认会话有效才继续无名称转发，不会因名称不受支持而跳过身份校验或 VPN 回环保护。

## 移动端开发配套

Android 构建明确 NDK 目标架构和 C++ 运行库，双 ABI APK 同时检查 ELF 架构、动态依赖及运行库打包。iOS 宿主与 Packet Tunnel 补齐 C++ 运行库链接。Android 重启烟测在执行真实请求前等待 VPN 与进程代理选择一致，原 TUN 来源断言保留。

这些是移动端开发与验证改动，本次仍只发布桌面正式安装包。Android/iOS 没有经过目标设备验收，不发布正式移动安装包。

## 验证与待办

设备名称的 Rust 网关、来源序列化、Java 编码及协议兼容回归已本机通过，完整前端回归、类型检查与生产构建通过。本次同源跨平台 Check、Android 模拟器及四平台打包结果以正式发布记录为准；iOS 已通过相关源码的 Mac 模拟器及无签名 iPhone 编译。

扫码配对到 VPN 远程流量的完整设备验收、持续 HTTP 会话与响应观察、HTTPS 可选解密、M1 实机安装和跨版本更新仍待处理。无 CA 的局域网模式只记录连接及可见 HTTP 元数据，不代表可以查看 HTTPS 正文。详见[局域网协同抓包](mobile-lan-capture.md)和[开发清单](roadmap.md)。

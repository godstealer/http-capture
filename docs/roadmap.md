## 已确认的设计约定

- 保留 Tauri + React + Rust core，单仓库多模块。
- 多个发送引擎并存，按请求动态选择；不因新增引擎推翻现有工程。
- 新建请求默认 Auto、空 URL、通用请求头和默认 TLS；不预置空请求标签。
- 编辑捕获请求创建新草稿，发送前响应为空。实际创建的标签可恢复，启动默认进入抓包页。
- 抓包和手动发送共用发送、脚本及拦截业务逻辑。
- 拦截根据规则匹配；没有规则时不暂停任何请求。
- 手动请求默认直连，可独立选择已保存的代理，不改变抓包的全局代理。
- 代理和协议发送失败不静默回退直连或切换协议重试。
- 区分客户端原始字段顺序、实际上游发送字段顺序与协议编码字节，不宣称整个连接逐字节保真。
- **两引擎指纹对比已取消，不列入待办。** 对功能正确性和保序能力的必要测试仍应执行。

## 按顺序推进的任务与验收标准

### R1：独立发送、并行发送和取消（已实现并通过 GUI 复核）

- [x] 用每标签状态替换全局 busy，结果始终写回原始标签。
- [x] 为执行分配稳定 ID，core 提供取消接口，HTTP/IPC 共用。
- [x] 取消能终止网络 I/O、脚本等待和拦截等待，记录清楚的取消原因。
- [x] 定义发送中编辑、重复点击发送和关闭标签的行为。
- [x] 自动化验收：并发发送、独立取消、无孤立等待项、结果按标签回填；实际 GUI 点击复核见下方未勾选项。

主要入口：`apps/frontend/src/App.tsx`、`crates/capture-core/src/lib.rs`、`crates/capture-service/src/main.rs`、`apps/desktop/src-tauri/src/main.rs`。

行为约定：

- 每个标签同一时刻只运行一次；不同标签可以并行，结果按标签 ID 回填，不切换当前焦点。
- 点击发送时克隆草稿，清空旧响应。发送期间允许编辑，修改仅影响下次发送；如果草稿已改动，本次脚本生成的请求/变量不覆盖当前草稿，仍可在重放历史中查看。
- 关闭发送中的标签会请求取消；结果仍落盘到历史，不重新创建标签。取消请求已到达服务器后，不会撤销服务器已经完成的业务操作。
- 先通过 `prepare_replay` 预留执行 ID，再调用 `replay_request`，解决“刚点发送就取消”的竞态；`cancel_replay` 供 HTTP 和 Tauri 共用。执行 ID 同时是记录 ID，完成后移出执行表，不能重复提交。
- 未开始的预留有效期 60 秒，下次预留时回收；最多保留 128 个执行/预留。发送中的状态不写入工作区，不会在重启时自动重发。
- 取消会丢弃网络发送 future，清除拦截等待，并通知 QuickJS 在中断检查点停止；同步原生脚本工具调用不能在调用中途强制抢占。原有脚本 2 秒限时仍保留。
- 取消失败允许重试；连接断开且无法确认取消时提示用户检查历史/拦截列表。页面刷新、进程异常退出后的执行恢复不在本阶段范围。

# HTTP Capture 0.1.32 发布说明（2026-10-20，自动响应重写）

**发布准备中，最终版本以 CI 为准。** 本轮计划发布 0.1.32，包含基于 `7054061` 完成的自动响应重写、编辑一致性修复及正文读取基础接口；正式来源提交、构建和公开附件核验结果将在发布后补记。当前已发布版本仍为 [0.1.31](https://github.com/godstealer/http-capture/releases/tag/build-da127ea9ba1a)，历史说明见[上一版记录](release-2026-10-20.md)。

## 更新内容

- **自动替换整份响应**：新增“响应重写”页面，按 URL、精确域名和可选方法匹配，统一替换状态码、有序响应头及完整正文。支持 UTF-8、Base64 和本地文件；保存并启用后处理后续匹配响应，无需逐次暂停放行。
- **文本与正则局部修改**：保持状态码，按修改项顺序替换 UTF-8 正文，或设置、查找替换、删除响应头。支持正则分组、大小写和首次/全部匹配；保留重复字段及相对顺序，Set-Cookie 不自动合并。支持常见压缩正文受限解压，实际修改后重算长度和清理失效编码、摘要等头。
- **自动与手动入口分开**：侧栏、抓包详情及右键提供“自动替换响应 / 自动修改响应”；原队列入口明确为“手动响应断点”。捕获模板默认禁用，按完整 URL 和请求方法建立草稿，编辑保存后再产生新请求，不改写已经完成的历史记录。
- **顺序、回滚与原件保留**：自动重写仍正常访问上游，在响应后插件/脚本之后、手动响应断点之前运行。全部匹配规则按列表顺序执行，每条规则失败只回滚该条修改并记录原因，后续规则继续；最早原始响应继续保留。规则持久保存，支持开关、排序、复制、搜索和版本冲突保护。
- **正文编辑与摘要头一致性**：修改替换正文或读入文件后移除失效的 Content-Digest、Repr-Digest 等校验头，避免新正文携带旧摘要；原样重复输入保留原头。响应头编辑明确响应语境，避免把响应字段当作请求头处理。
- **响应规则可迁移**：全局配置增加“响应重写规则”类别。默认不导出可能含正文、头值或匹配凭据的规则，勾选“包含请求内容和变量值”后才带入；导出、导入均关闭总开关和各条规则，导入后重启并审阅启用。标准 JSON 仍不加密，旧包缺少该类别也可导入。
- **正文读取后端基础**：新增完整历史元数据、四个 HTTP 实体正文引用、版本化范围读取和完整原始实体导出接口，接入 HTTP 与桌面 IPC；去除无人消费的桌面完整 Flow 事件转发。全部历史和完整正文语义保留，前端仍走全量读取，P0 全链路低内存尚未完成。

## 从哪里使用

打开侧栏 **响应重写**，选择 **替换整份响应** 或 **修改部分内容**，填写匹配和内容后点击 **保存并启用此规则**。该按钮同时开启总开关与当前规则；“保存全部规则”保留当前开关状态。关闭时取消总开关并保存，手动响应断点仍按其自己的开关工作。

详细步骤和限制见[自动响应重写](response-rewrite.md)，配置导出/导入见[设备迁移说明](config-migration.md)，大正文后续工作见[正文内存改造](body-memory.md)。

## 验证与边界

本地完整 capture-core、capture-service、MCP 和传输层回归、前端 38 项回归、TypeScript、国际化、Vite 生产构建及桌面端含测试代码的编译检查已通过。摘要头修复后，模型与组件定向回归和生产构建再次通过；内置浏览器隔离检查覆盖两种规则编辑、保存启用和窄窗口布局。最终跨平台 CI、安装包构建、签名及公开附件核验仍待本次发布流程确认，不把本地通过写成已经发布。

自动响应重写最多 32 条规则、每条最多 32 个修改项。整份替换最多 8 MiB；文本修改的输入、每步解压和替换结果也受 8 MiB 限制。这是重写功能的限制，不重新限制普通 HTTP 抓包正文。文本必须是有效 UTF-8 且不含 NUL，显式非 UTF-8 字符集和二进制类型不做局部正文修改；可使用整份文件/Base64 替换。

HEAD、204、205、206、304 不做局部正文修改；整份替换按 HTTP 无正文规则处理 HEAD/204/205/304。WebSocket、SSE、gRPC 流式响应跳过自动重写。上游失败不返回预设成功响应，也不因重写重发原请求。

新增正文接口每次范围读取最多 64 KiB，完整导出仍有 256 MiB 上限。HTTP 下载先完成私有临时文件复制并释放数据库锁，再分块发送，避免慢客户端占用数据库；旧完整 Flow 接口兼容。前端、脚本/helper、内部正文模型及长连接路径仍有完整正文缓冲，整进程并发峰值尚未验收，不能称 P0 已完成。

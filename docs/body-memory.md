# 大正文内存改造

更新时间：2026-10-20。正式版 0.1.19 已包含网络正文分块暂存，共享与序列化改造随 [0.1.23](release-2026-10-19.md) 发布；[0.1.31](release-2026-10-20.md) 已交付 MCP 64 KiB 范围读取及 Spool 有界读取。本次新增历史元数据和正文引用接口仍是**未发布开发增量**，前端尚未切换，全链路 P0 未完成。实机大文件和并发峰值验收继续暂缓。

## 已实现的阶段

- HTTP 请求和响应的 `body_base64` 使用 `SharedBody(Arc<String>)`。从已有 String 转入时保留原缓冲区及容量，克隆模型只增加引用，修改通过写时复制隔离。
- Flow、原始请求/响应、广播订阅和拦截快照因此共享同一正文。SQLite 元数据克隆仍借用共享正文，写入 BLOB 后给副本赋 marker，不先复制整块 String。
- Base64、公开 JSON 字段、数据库结构和前端接口不变；反序列化仍严格要求字符串，缺字段或 null 不自动变为空正文。
- Rust 调用方构造 `RequestDraft`/`CapturedResponse` 时，String 正文需要 `.into()` 转入 `SharedBody`，读取可借用 `as_str()`/`as_bytes()`；这是 Rust 字段类型变更，JSON 调用方不需要适配。
- 脚本输入借用正文直接序列化到 JSON，仅小型元数据保留有序 Value，保持既有 `Object.keys`/`JSON.stringify` 属性顺序，不再给实体正文构造中间 Value。脚本只改头部等元数据时，返回正文复用原缓冲区；脚本内部仍会解析和生成完整正文。
- httpcloak helper 的输入使用借用投影直接序列化，普通/伪头按原序过滤禁用项，正文和不要求 Clone 的脚本配置均借用，不再创建完整中间 Value。helper 仍接收完整 JSON。

- transport-api 的 9 项回归验证原缓冲区/容量保留、32 个 8 MiB 正文克隆共享、唯一持有者修改、共享修改隔离及 JSON 兼容。
- 内核全量回归通过，包括 SQLite BLOB 事务/损坏回滚/重开/备份、H1/H2/H3、广播、拦截、脚本、取消、SSE、gRPC 和 WebSocket；系统凭据库及可选 TUN helper 测试按各自条件忽略。
- 两个内存事件订阅者和拦截快照直接比较非空正文缓冲区地址；数据库重新读取会产生新分配，不将其视为应共享的对象。
- 控制服务 4 项契约测试通过，包含大正文工作区和集合重启恢复。
- helper 的 3 项输入契约测试覆盖全部字段、非 Clone 脚本、禁用/重复头、二进制正文、null 及代理字段，借用投影不改动原始请求。
- 桌面、控制服务和可选 browser-replay/wreq 引擎编译通过。
- 后续序列化改动完成后，脚本/插件/取消/拦截/helper 共 20 项集成回归再次通过；未修改正文的脚本保留原缓冲区，修改正文的既有回归仍保持原行为。
- 脚本输入的 3 项兼容测试与旧 JSON 字节逐一对照，覆盖嵌套配置、TLS/证书、null 和空实体；运行时检查属性枚举和 stringify 顺序。

上述指针和容量测试证明避免特定副本，不等于测量整进程内存峰值。

## 本次开发增量：历史与正文读取接口（未发布）

旧版历史列表、详情会一起还原完整 Base64。开发版新增独立的 `FlowMetadata`，在 SQL 中移除请求、响应、原始请求、原始响应四个实体的 `bodyBase64`，其他字段保留；通过 `bodyReferences` 提供实际存在槽位的字节长度。未加载正文用引用表示，不用空串冒充空正文，也不把元数据直接当作可发送、保存或导出的完整 Flow。

| 新接口 | 行为 |
| --- | --- |
| 历史元数据和变化读取 | 保留全部历史、顺序、增量版本和删除记录，不套用 MCP 的 200 条分页上限，也不按数量丢弃历史 |
| 元数据 / 显式完整读取 | 使用该条记录的 `bodyRevision`；完整 Flow 只在显式调用时还原正文，旧 `list/get/changes` 继续兼容完整内容 |
| 版本化正文范围读取 | 四个固定实体槽，每次 1–65536 字节；版本检查和 BLOB/旧 inline 范围读取在同一事务中，更新、删除或内核重开后旧引用拒绝继续读取 |
| 完整原始实体导出 | 在同一版本快照分块复制；本机写下载目录的随机文件，完成验证后才发布目标文件。HTTP 先完整复制到私有临时文件并释放数据库锁，再每块最多 64 KiB 传给浏览器，取消时清理；仍沿用 256 MiB 导出上限 |

范围读取的 Base64 表示精确原始字节；只有整段恰好是合法 UTF-8 时才附带文本，不把截断的字符替换为乱码。完整导出保存原内容编码的实体字节，不自动解压。校验失败不会把有限前缀标成完整导出，也不会退回旧版本正文。

桌面外壳同时移除无人消费的 `flow-recorded` 完整 Flow 事件转发，避免额外序列化全部正文；内核内部广播保持既有语义。**当前前端仍调用完整历史/正文接口，列表、详情、复制、重放、会话导出及编辑器未完成按需引用切换。** 这次仅打通后端、HTTP 和桌面 IPC 的可用接口，不代表界面内存已经下降到恒定值。

新增回归覆盖超过 200 条完整历史、四槽与真空正文、BLOB/旧 inline 的精确范围、损坏引用、逐条版本及重开、另一 SQLite 连接更新/删除时的快照、导出取消和 HTTP 分块/鉴权，已随本轮 core/service 回归及桌面编译检查通过。旧 inline JSON 仍需 SQLite 内部解析，WebSocket 帧正文格式没有改变；没有声称全链路无全量解析或完整文件引用完成。

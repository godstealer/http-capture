## 已实现的阶段

- HTTP 请求和响应的 `body_base64` 使用 `SharedBody(Arc<String>)`。从已有 String 转入时保留原缓冲区及容量，克隆模型只增加引用，修改通过写时复制隔离。
- Flow、原始请求/响应、广播订阅和拦截快照因此共享同一正文。SQLite 元数据克隆仍借用共享正文，写入 BLOB 后给副本赋 marker，不先复制整块 String。
- Base64、公开 JSON 字段、数据库结构和前端接口不变；反序列化仍严格要求字符串，缺字段或 null 不自动变为空正文。
- Rust 调用方构造 `RequestDraft`/`CapturedResponse` 时，String 正文需要 `.into()` 转入 `SharedBody`，读取可借用 `as_str()`/`as_bytes()`；这是 Rust 字段类型变更，JSON 调用方不需要适配。
- 脚本输入借用正文直接序列化到 JSON，仅小型元数据保留有序 Value，保持既有 `Object.keys`/`JSON.stringify` 属性顺序，不再给实体正文构造中间 Value。脚本只改头部等元数据时，返回正文复用原缓冲区；脚本内部仍会解析和生成完整正文。
- httpcloak helper 的输入使用借用投影直接序列化，普通/伪头按原序过滤禁用项，正文和不要求 Clone 的脚本配置均借用，不再创建完整中间 Value。helper 仍接收完整 JSON。

## 历史与正文读取基础接口（0.1.33 已发布）

旧版历史列表、详情会一起还原完整 Base64。0.1.33 新增独立的 `FlowMetadata`，在 SQL 中移除请求、响应、原始请求、原始响应四个实体的 `bodyBase64`，其他字段保留；通过 `bodyReferences` 提供实际存在槽位的字节长度。未加载正文用引用表示，不用空串冒充空正文，也不把元数据直接当作可发送、保存或导出的完整 Flow。

| 新接口 | 行为 |
| --- | --- |
| 历史元数据和变化读取 | 保留全部历史、顺序、增量版本和删除记录，不套用 MCP 的 200 条分页上限，也不按数量丢弃历史 |
| 元数据 / 显式完整读取 | 使用该条记录的 `bodyRevision`；完整 Flow 只在显式调用时还原正文，旧 `list/get/changes` 继续兼容完整内容 |
| 版本化正文范围读取 | 四个固定实体槽，每次 1–65536 字节；版本检查和 BLOB/旧 inline 范围读取在同一事务中，更新、删除或内核重开后旧引用拒绝继续读取 |
| 完整原始实体导出 | 在同一版本快照分块复制；本机写下载目录的随机文件，完成验证后才发布目标文件。HTTP 先完整复制到私有临时文件并释放数据库锁，再每块最多 64 KiB 传给浏览器，取消时清理；仍沿用 256 MiB 导出上限 |

范围读取的 Base64 表示精确原始字节；只有整段恰好是合法 UTF-8 时才附带文本，不把截断的字符替换为乱码。完整导出保存原内容编码的实体字节，不自动解压。校验失败不会把有限前缀标成完整导出，也不会退回旧版本正文。

桌面外壳同时移除无人消费的 `flow-recorded` 完整 Flow 事件转发，避免额外序列化全部正文；内核内部广播保持既有语义。原未发布的 0.1.32 来源只有后端基础接口，前端仍全量读取；0.1.33 同时交付下面的前端切换。原来源的七条摘要继续保留在[未发布候选记录](release-2026-10-20-response-rewrite.md)，不会被改写为当时已经包含前端阶段。

新增回归覆盖超过 200 条完整历史、四槽与真空正文、BLOB/旧 inline 的精确范围、损坏引用、逐条版本及重开、另一 SQLite 连接更新/删除时的快照、导出取消和 HTTP 分块/鉴权，已随本轮 core/service 回归及桌面编译检查通过。旧 inline JSON 仍需 SQLite 内部解析，WebSocket 帧正文格式没有改变；没有声称全链路无全量解析或完整文件引用完成。

## 前端按需读取与完整实体处理（0.1.33 已发布）

本节记录 0.1.33 已交付的前端范围，与上述后端接口使用同一发布来源。本地 44 个前端模型/组件回归脚本、国际化、TypeScript 与 Vite 生产构建已通过；内置浏览器隔离验收已完成，覆盖真实分页、完整处理、编码边界、空实体和单响应模板；原生与目标机器验收继续单列。同一来源的跨平台 CI、四平台构建、原生更新测试、签名和公开附件核验已通过；目标机器实测仍需单独验收。

现代内核的历史列表和增量轮询读取独立 `FlowMetadata`，不携带上述四个 HTTP 实体的 Base64 正文，仍保留全部历史、过滤、排序和选择语义。元数据不伪装成空正文的完整 Flow。只有旧内核明确缺少对应端点时，才回退兼容的完整历史接口；鉴权、存储、版本或网络错误不会触发全量回退。

选中记录的正文按实体和 `bodyRevision` 读取，每页最多 64 KiB。切换记录、实体、版本，隐藏面板或断开内核后，不继续应用旧的异步读取和解析结果，并释放界面持有的片段与已加载正文。记录变化或删除导致版本校验失败时，需要重读元数据；不混合新旧片段，不回退到旧正文。

| 所选 HTTP 实体大小 | 查看方式 |
| --- | --- |
| 不超过 64 KiB | 该片段确认包含完整实体后，默认正文页才挂载既有 `ResponseBody`，继续提供格式化、解码和静态预览能力 |
| 大于 64 KiB、不超过 8 MiB | 默认分页；正文页点击“加载完整正文用于格式化或预览”后，逐个读取同一版本的 64 KiB 片段，拼成所选实体，再使用格式化或 SVG 等预览；不通过 `get_flow` 顺带读入其他三个正文槽，原文/Base64 页仍按片段查看 |
| 大于 8 MiB | 保留原始片段的文本、Hex、Base64 查看和完整原始实体下载，不自动拼接完整正文送入格式化或预览 |

有限片段明确标注为片段，复制只包含当前片段；内容编码、二进制或被截断的 UTF-8 不能当作完整文本解压、格式化或预览。完整处理会占用所选实体及其解析结果的内存，继续遵守既有 8 MiB 解压输出保护及格式化自身限制。切换页码也会释放显式完整缓存；这些是界面操作预算，不重新限制普通抓包正文。

完整操作仍保持完整内容语义。复制完整 cURL/JSON、编辑或发送到重放，显式按记录版本调用 `get_flow`；读取失败不复制前缀或创建缺正文草稿。会话 JSON/HAR 导出逐条还原固定版本的完整记录，再聚合序列化；支持文件选择 API 的浏览器先选择位置，取消后不读取正文。原生保存及没有该 API 的浏览器仍有完整聚合缓冲，导出不是恒定内存的流式 JSON/HAR。

“下载完整原始实体”独立于预览：桌面按版本分块写入私有文件，完成后原子发布；HTTP 服务先准备完整私有临时文件并释放数据库锁，再分块发送。支持浏览器文件选择 API 时按背压流式写入；无该 API 时回退完整 Blob 缓冲，界面明确提示。此下载保留原始内容编码，当前上限为 256 MiB；不是只保存当前页，也不借此声称浏览器 Blob 路径低内存。

隐藏的 HTTP 响应页不挂载正文解析/格式化 Worker。gRPC 会话面板保持挂载，切换标签不取消实际调用，但隐藏或断线时不读取和解码记录正文；四个实体合计不超过 64 KiB 时可自动完整加载，较大的记录要明确选择“加载完整 gRPC 正文”。该操作读取完整 Flow 后解析，不把前缀当作完整消息；大 gRPC 正文、gzip 解压后的消息预算和长会话累计内存仍是后续工作。

本轮 44 个前端脚本的模型与真实组件回归已通过，覆盖 15,003 条完整元数据历史、删除/reset/重开、版本固定的完整操作、分页与精确边界、选择/隐藏/断线后的旧结果、下载取消、所选实体完整处理和 gRPC 会话保留。国际化、TypeScript 和 Vite 生产构建通过。内置浏览器已完成 production-dist 隔离界面验收，使用四条合成记录：约 150 KB JSON 默认按片段显示，第 3 页可读到尾部，第 4 页报无效页码；显式完整处理后才进行完整 JSON 格式化。raw gzip 保留原始字节，跨 UTF-8 字符边界的片段禁用文本并转为 Hex；真正 0 字节的 originalRequest 显示空正文，63 字节的小响应默认完整格式化。小响应生成的整份替换模板与完整原文一致，真实横向/纵向滚动可到达分页。

本次浏览器读取记录均为不超过 65536 字节、固定版本的 `read_flow_body`，未调用 `flows/get` 或旧完整历史接口；单响应模板也仅读取 response 实体。这是本地合成数据的界面证据，不代表原生文件选择、安装、跨设备或大文件峰值实测。 跨平台 CI 与公开附件核验现已完成；原生文件操作、旧内核兼容、大文件及并发峰值手工验收继续暂缓。
